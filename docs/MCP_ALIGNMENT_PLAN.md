# Creator 2.4 工具能力对齐计划

## 目标

在现有 Creator 2.4.15 桥接器上对齐 3.8 MCP 的工具组织方式和通用 JavaScript 执行能力，复用现有编辑器工具及场景 IPC，保留旧入口兼容性，不修改游戏业务和资源。

## 实现步骤与验收

1. 工具细化与分类 → 验证：独立工具具有明确参数、分类、只读标记，并映射现有操作；目录列出开放状态。
2. editor / scene JavaScript 执行 → 验证：同步返回、异步返回、函数导出、日志、异常、超时、不可序列化结果和项目身份校验。
3. 开放范围统一 → 验证：预设及操作白名单作用于 stdio、HTTP、批处理；配置变化重新加载目录；旧配置继续有效。
4. 面板按分类勾选 → 验证：预设切换、搜索、分类全选及清除、保存导入导出，并截图核对界面。
5. 文档与构建 → 验证：更新工具说明、能力对应关系与限制；运行受影响测试组并生成可加载构建产物。

## 实现约定

- 沿用仓库现有 TypeScript 源码与 CommonJS 构建链，以共享项目规则和实际架构为准。
- editor 上下文访问主进程 Editor / Node 能力，scene 上下文通过场景 IPC 访问 cc；不把二者混为游戏预览上下文。
- 通用脚本具备当前编辑器进程权限，工具预设用于控制是否开放；不声称脚本执行是安全沙箱。
- 超时响应不等于已取消脚本副作用；同步死循环不具备跨进程强制终止保证，必须如实说明。
- 保存配置后动态刷新可用工具；保留连接工具和现有工程身份保护。
